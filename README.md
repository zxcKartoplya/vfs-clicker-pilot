# VFS Clicker Pilot

Каркас пилота для запуска одного фиксированного браузерного сценария в нескольких изолированных сессиях.

Сейчас проект проверяет архитектуру на локальной демонстрационной странице. Реальные аккаунты, пароли и прокси в репозитории не хранятся.

## Возможности

- до 10 параллельных браузерных контекстов;
- отдельные cookies и хранилище для каждой сессии;
- индивидуальный прокси или общий тестовый прокси;
- локальный мост для SOCKS5-прокси с логином и паролем;
- независимые результаты и ошибки по аккаунтам;
- заменяемый обработчик CAPTCHA;
- отдельные классы сценариев без изменения ядра запуска;
- сценарий входа VFS с семантическими локаторами;
- заполнение первого шага новой записи без перехода по кнопке `Continue`;
- распознавание проверок до и после отправки формы;
- безопасный вывод текущего этапа для каждой сессии.

## Установка

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[dev]'
```

Playwright использует установленный Google Chrome, поэтому отдельная загрузка Chromium не требуется.

Авторизованный SOCKS5-прокси автоматически преобразуется в локальный SOCKS5 без авторизации. Локальный порт существует только во время запуска и закрывается вместе с программой.

## Локальная проверка

```bash
cp examples/config.example.json config.json
.venv/bin/vfs-clicker --config config.json --demo
.venv/bin/pytest
```

Файл `config.json` исключён из Git. Для реальной проверки его нужно заполнить локально и не отправлять в репозиторий.
Параметр `timeout_seconds` задаёт лимит ожидания браузерных действий и загрузки страницы.

## Подтверждённое ограничение VFS

Публичная точка входа VFS отвечает Cloudflare-челленджем. Автоматический обход защиты не реализуется. Сценарий распознаёт проверку и переводит конкретную сессию в ручное подтверждение. После разрешённого подтверждения выполнение продолжается по фиксированной цепочке.

После локального заполнения `config.json` сценарий входа запускается так:

```bash
.venv/bin/vfs-clicker --config config.json --vfs-login
```

Для VFS рекомендуется режим ручной передачи обычного Chrome:

```bash
.venv/bin/vfs-clicker --config config.json --vfs-login --chrome-handoff
```

Пилот этого режима запускает один аккаунт. Программа открывает обычный Chrome с отдельным профилем и настроенным прокси. Нужно вручную пройти Cloudflare, дождаться формы входа или уже открытого кабинета и только затем нажать Enter в терминале. После этого кликер отклоняет необязательные cookies, заполняет форму и при необходимости просит вручную пройти CAPTCHA внутри формы. После авторизации кликер открывает `Start New Booking`, выбирает первые доступные значения на шаге `Appointment Details` и останавливается перед кнопкой `Continue`. Второй Enter после завершения сценария закрывает окно.

Профили сохраняются в `.vfs-profiles/` и не попадают в Git. В них остаются cookies и локальное состояние браузера, поэтому их нельзя передавать другим людям.

Для сравнительной диагностики без изменения конфигурации прокси можно временно отключить:

```bash
.venv/bin/vfs-clicker --config config.json --vfs-login --no-proxy
```

Флаг `--no-proxy` можно совместить с `--chrome-handoff`.

Для ручного подтверждения Cloudflare параметр `headless` в конфигурации должен быть `false`.

Во время запуска терминал показывает этапы без email, паролей и данных прокси. После строки `Cloudflare verification detected` нужно пройти проверку в браузере и нажать Enter в терминале. Успешное завершение проверки подтверждается только после появления формы входа. Если Cloudflare остаётся на странице, программа рекомендует повторить запуск с другим прокси или `--no-proxy`. Если после отправки формы VFS показывает ещё одну проверку, появится отдельная строка `additional verification detected after submit`.
